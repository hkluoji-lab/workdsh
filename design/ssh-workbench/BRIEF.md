# 用户需求与本版假设

编号：BRIEF-DSH-SSH-001
日期：2026-09-08
状态：用户输入摘要；设计假设待评审

## 用户已明确的需求

1. 分析并借鉴 https://www.terminal.icu/ 的产品体验。
2. 准备使用 https://github.com/anywhere-labs/dsh-desktop 为基础开发。
3. 能自己配置大模型，使用过程中可随时呼唤 AI 帮助。
4. 关注 XTerminal Pro 的付费限制，希望自主配置模型。
5. 当前先形成“功能清单的明细和原型”。

## 本轮交付边界

- 详细功能清单：需求编号、模块、目标能力、优先级、验收条件、异常边界、原型覆盖。
- 独立可点击原型：终端工作区、主机、模型、AI、文件、快捷命令、记录及设置。
- 不将模拟原型描述为已完成真实 SSH、AI 或文件操作。

## 用于设计的假设（未逐项获得用户确认）

- 暂定产品名 DSH Terminal。
- 首要人群是个人开发者和运维人员。
- macOS 和 Windows 优先，远程 Linux 优先。
- 核心工作流程无需产品账号，自带模型配置免费开放。
- P0 以手动终端和 AI 建议为主；协助执行作为 P1，并提前展示交互。
- 采用深色终端优先布局与可收起 AI 面板。

## 已查证的竞品边界

XTerminal 官方“小易”文档将自定义 Anthropic/OpenAI 兼容接口列为 Pro 可用，并列出密钥、地址和模型配置。未安装实测各发行版本，因此不宣称“Pro 也完全不能配置”。

来源：https://docs.xterminal.cn/advanced/xiaoyi/

## 补充输入：文件工作区

用户认可原型，并强调 SSH 工具必须支持文件上传，提供 XTerminal 截图作为布局参考。截图展示左侧远程目录树、中间上方文件编辑器与下方终端、右侧传输管理。基于此，将文件编辑纳入 P0，新增组合布局、多文件草稿、拖放上传、同名冲突和队列恢复的详细需求。样例均使用虚构主机与路径，不复用截图中的实际服务器信息。

用户进一步提供控制台、连接中心和文件工作区三张截图，强调顶部的重要性。设计调整为：顶部全局功能入口 + 主机会话标签 + AI/设置；左侧仅保留当前工作区工具；文件标签位于主机内部。截图仅作为视觉与信息层级参考，不导入其中的主机数据或备注内容。
