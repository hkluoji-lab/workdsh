# DSH Terminal：功能明细与交互原型

产品设计稿 v0.1 · 2026-09-08 · 待评审

## 打开原型

直接用浏览器打开本目录的 [index.html](index.html)，也可以从仓库根目录启动本地静态服务：

```sh
python3 -m http.server 4179 --bind 127.0.0.1 --directory design/ssh-workbench
```

然后访问 http://127.0.0.1:4179/ 。端口被占用时可换用其他端口。无需安装依赖，也无需启动 Electron。

所有主机、终端、AI、模型能力测试、远程文件和监控指标均为模拟数据；没有真实网络请求、命令执行或上传。请勿在原型中输入真实凭据。表单里的密钥不存储、不发送。业务样例和设置在刷新后重置。

## 建议体验顺序

1. 默认终端中点击“分析错误”，查看 AI 建议。
2. 点击“填入终端”，再按回车执行模拟的 nginx -t。
3. 切换 AI 到“协助”，体验目标和命令确认。
4. 打开“文件工作区”，展开目录、编辑 application.yml、保存，或关闭未保存的标签。
5. 点击“上传”，选择同名处理方式，开始模拟传输，体验暂停、失败与重试；从编辑器点击“询问 AI”。
6. 从顶部标签切换到 staging-api，确认终端和 AI 对话相互独立。
7. 顶部“连接中心”中添加主机，体验必填校验和首次连接指纹确认。
8. “模型服务”中新增配置，选择成功、仅问答、认证失败或超时场景。
9. “监控样例”中模拟断开连接，再显式重连。
10. “功能清单”中搜索和筛选全部需求，点击查看验收条件。

AI 输入“模拟失败”可查看超时降级；“检查磁盘占用”有预置回答。其他自由问题只使用有限场景模拟，不调用大模型。

终端输入 help 查看预置命令。未知命令只记录输入并说明无预置结果，不作为真实执行。

## 文件

| 文件 | 用途 |
|---|---|
| [FEATURES.md](FEATURES.md) | 完整功能清单、旅程、验收、边界与追溯元数据 |
| [BRIEF.md](BRIEF.md) | 用户输入和明确标注的设计假设 |

修改 feature-data.js 后，用符合仓库要求的 Node 22.19+ 或 24+ 运行：

```sh
node design/ssh-workbench/build-docs.mjs
```

原型仅作为设计资产，不加入根工作区依赖，不改变 DSH Desktop 和上游子模块。

## 顶部设计

全局入口与主机会话标签固定在顶部；文件标签属于当前主机，显示在编辑器上方。左侧收为窄工具栏。顶部 AI 按钮在文件页直接打开文件侧边助手，⌘ / Ctrl + J 同样可用。完整三栏布局建议在 1200px 以上窗口体验。
