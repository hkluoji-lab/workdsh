# 定时任务交互与视觉规范

状态：设计基线 0.1，2026-09-25。**待实施验证。**

本文件只描述定时任务页面的增量规则。通用约束一律以 [WorkDSH 页面风格与交互规范](../../UI-DESIGN.md) 为准；本文件与之冲突时以 UI-DESIGN 为准。不因对标同类产品另起视觉风格，不引入第二套主题或组件库。

## 1. 入口与所有权

| 项 | 规则 |
| --- | --- |
| 导航行 | 通过公开 `sidebar.panellist` 增量注册，`main` 使用相同 key（`workdsh-automation`），`order` 保持 40 不变 |
| 当前状态 | 该行由工作台作为待开放占位登记，标签追加「待开放」，配对面板只说明未实现原因与可替代路径 |
| 实现后 | 按助理、项目、资料库的既有移交范式，把「定时任务」的 `main` 面板交还 automations 自持，工作台 `businessPanels` 同步移除该项；两包需同批安装 |
| 禁止 | 不替换或复制官方 Workspace / Session / New Session / Settings owner；不用 `sidebar-right` 承担该入口 |
| 入口可见性 | 安装、授权与能力健康三者共同决定；隐藏入口不算鉴权 |

「定时任务」既是全局主导航页面，也是项目配置侧栏的一个卡片（UI-DESIGN 第 10 节）。两处的数据来自同一个领域服务，项目侧栏只过滤出该项目的规则。

## 2. 页面骨架

### 2.1 定时任务列表（`main`）

- 顶部为标题行与「新建定时任务」主操作，右侧排序与状态筛选（全部 / 运行中 / 已暂停 / 已归档）。
- 列表行字段：名称、状态、下次运行时间、最近一次运行结果、关联项目、执行主体。
- 状态用 6px CSS 状态点（UI-DESIGN 第 10 节），**必须同时给出文字或可访问说明**，不能只靠颜色传达"运行中/已暂停/失败"。
- 名称为 13px/20px，时间为 11px/18px，名称与时间左边线对齐；长名称单行省略且完整名称可访问。
- 空状态：简短说明并给一个主要下一步（新建定时任务）；与"筛选无结果"分开呈现。
- 行内操作：启用/暂停、立即运行、编辑、归档。归档为危险操作，需解释影响；已归档规则不出现在默认列表。

### 2.2 详情与编辑

- 新建与编辑使用页面或共享 Modal，字段分组为：基本（名称、说明）、计划（规则形态、cron 表达式、时区、生效区间）、执行（专家、项目、连接器、工作区、任务描述）、状态。
- 计划分组必须显示**未来运行时间预览**（AU-R-08）：按当前规则与实际时区算出接下来若干次触发时刻，规则非法时给出行内错误而不是静默失败。
- 执行主体沿用任务创建器的公开接口：专家走专家插件的 `prepare-execution` / `create-execution`；项目走项目服务；连接器走连接器服务。不可用的选项显示明确原因，不返回空列表冒充"没有可选项"。
- 保存形成新修订；并发保存冲突必须可见，不静默覆盖（沿用既定 `expectedRevision` 语义）。
- 已产生运行的规则修改计划后，历史运行记录仍指向当时的规则修订。

### 2.3 运行历史

- 每条运行显示：来源（定时 / 手动 / Webhook）、状态、发生时间、是否跳过及跳过原因、会话入口、耗时。
- 会话入口跳转到真实原生 Session；没有会话的运行（如被跳过）不提供会话链接，也不假装存在。
- 失败原因使用领域错误码的可读映射，同时保留原始码供排查；不使用"已完成"这类与回执不符的措辞。
- 运行记录只读，不提供"编辑运行结果"。

### 2.4 项目配置侧栏卡片

- 显示该项目下的规则名称、下次运行时间与 6px 状态点，名称 13px/20px、时间 11px/18px。
- 只显示当前主体可见的规则，数量与列表页一致（UI09）。
- 底部保留"查看全部"文字按钮，进入全局列表并按项目预筛选。

## 3. 状态与交互覆盖

每个页面必须覆盖 [UI-DESIGN 第 6 节](../../UI-DESIGN.md) 要求的全部状态，其中定时任务特有的：

| 状态 | 要求 |
| --- | --- |
| 加载 | 列表与详情分别有加载态；不使用骨架屏冒充真实数据 |
| 空数据 | 区分"还没有规则"与"筛选无结果" |
| 无权限 | 明确说明缺少哪项能力及修复入口，不展示可执行的假按钮 |
| 失效诊断 | 专家修订缺失、连接不可用、授权撤销时，在规则详情给出原因与修复入口；规则保持停止状态 |
| 提交中 | 保存、启用/暂停、立即运行分别有进行中状态；不乐观显示成功 |
| 冲突 | 并发保存与并发启停显示冲突并提供重新读取 |
| 结果未知 | 触发后无法确认 Session 是否创建时，显示为待对账而不是失败或成功 |
| 离线/重连 | 断连时明确提示，恢复后重新读取真实状态 |

## 4. 不做与边界

- 不放置无实现支撑的控件：预算、并发上限、时长上限、通知渠道、团队共享、模板市场在首期不出现，或明确标注"待开放"并说明替代路径。
- 不使用灰色假装禁用；真正禁用必须有 `disabled` / `aria-disabled` 与原因（UI-DESIGN 第 2 节）。
- 不显示他人规则；不显示用量、成功率等没有真实服务支撑的统计数字。
- 示例数据只出现在原型中；正式页面去掉开发标记与 Host/Remote 实现细节。
- 不对状态点使用字符黑圆点与全角空格定位。
