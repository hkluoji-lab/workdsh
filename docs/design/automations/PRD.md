# 定时任务需求 PRD

状态：设计基线 0.1，2026-09-25。对应 D12 / P2-03、P2-04。**待实施验证，不是功能已交付声明。**

## 1. 背景

线上侧栏「定时任务」是工作台登记的待开放占位入口（`id: workdsh-automation`，标签追加「待开放」），点击进入说明面板而非功能页面。用户反馈"定时任务功能无法使用"——准确结论是**尚未实现**，不是故障。本 PRD 定义它应该是什么、首期做到哪。

## 2. 用户目标

用户要的不是"提醒我"，而是"到点替我把这件事交给对的人跑一遍，并且我能看到它跑没跑、跑成没跑成"。具体要求：

1. 让重复性工作按计划自动发生（日报、周报、月报、定期巡检）。
2. 复用已有的专家、项目、连接器与资料，不必每次重配。
3. 每次自动运行都能落到一次真实任务里，可以打开会话看过程与成果。
4. 出问题时我自己能看见原因，而不是静默不跑或重复跑。

## 3. 首期范围

### 3.1 做

| 需求 | 内容 |
| --- | --- |
| AU-R-01 | 一个用户可管理多个定时任务，归属为个人级；关联项目不改变个人所有权 |
| AU-R-02 | 定时触发：5 字段 POSIX cron 表达式 + IANA 时区 |
| AU-R-03 | 规则形态覆盖一次性、每天、每周多天、每月多天，并支持生效区间 |
| AU-R-04 | 最小触发间隔 300 秒，与官方 Schedule 的下限口径一致 |
| AU-R-05 | 每次触发创建一次真实官方 Session，不新建执行器、不缓存执行状态 |
| AU-R-06 | 立即运行：手动触发一次，走与定时触发相同的运行模型 |
| AU-R-07 | 启用、暂停、归档；暂停期间不产生新 occurrence |
| AU-R-08 | 未来运行时间预览：显示规则接下来若干次实际触发时刻 |
| AU-R-09 | 运行记录：来源、状态、会话链接、起止时间、失败或跳过原因 |
| AU-R-10 | 幂等去重：同一次触发重复投递只产生一次运行 |
| AU-R-11 | 同任务默认不重叠；错过触发默认合并为一次待执行 |
| AU-R-12 | 跨重启恢复：调度由单一 Host 持久管理，Host 停机后恢复错过触发 |
| AU-R-13 | 触发时重新解析执行组合与主体，重查授权与连接状态；失效则停止并诊断 |
| AU-R-15 | 读取助理记录的 `trigger_schedule` 计划意图，向用户提示可创建规则；不自动建规则 |

### 3.2 后置

| 需求 | 内容 |
| --- | --- |
| AU-R-14 | Webhook 入站：先持久化 `source + deliveryId + ruleId` 幂等事实，再协调创建 Session；`202` 只表示接收 |

首期不做 Webhook 的理由：官方 `ctx.webhookRuntime` 是 fire-and-forget，原文明确"没有队列、重试、去重、执行状态、崩溃重放、Agent 状态监听器或完成结果"，而"重复交付可能创建重复 Session"。这条链路的失败模式最多，必须在 cron 主链路的去重与恢复已经稳定后再做。

### 3.3 明确不做

- 不复制业务规则、不建工作流引擎或通用流程引擎；定时任务只负责触发与运行归属。
- 不承诺 Host 离线执行，不做秒级 cron。
- 不做危险提交的自动重试；外部写入结果不确定时先核对。
- 不建立第二套执行状态或第二套会话列表。
- 不提供团队共享的定时任务；跨成员可见性属于后续阶段（见 J10-P2）。
- 不做任务模板市场或预置任务库。

## 4. 市场对标结论

对 7 家同类产品的此功能定义做了横向对照，用于校准口径，不用于复制产品文案。

| 产品 | 叫法 | 触发 | 一次触发等于 | 运行记录 |
| --- | --- | --- | --- | --- |
| WorkBuddy | 自动化 | 每天/每周/单次，支持每周多天、每月多天、生效区间 | 以当前登录身份发起一次 Agent 任务 | 有历史执行记录页 |
| Claude | scheduled deployment | POSIX cron + IANA 时区，分钟级 | 启动一次 session（须带至少一个 initial event） | run history |
| 阿里百炼 | 定时任务（资源名 Deployment） | 每小时/每天/工作日/每周/每月/自定义 cron + 时区 | 创建一次会话并发固定初始消息 | Run：来源/状态/会话/起止 |
| 扣子 Coze | 触发器 | 定时 + Webhook，最小间隔 1 分钟 | 执行提示词/插件/工作流 | — |
| Foundry | routine | schedule(cron，最小 5 分钟)/timer/github_issue/custom | 排队调用 agent | run record |
| Letta | schedules | 一次性/周期（cron 或 every） | 默认新建 conversation | `cron runs` |
| AgentsRoom | scheduled tasks | 每 N 分钟/小时/天/周/月/配额周期 | 在项目中生成真实 agent 会话 | 归档每次运行 |

抽出的 7 条共识，以及我们的采纳情况：

| 共识 | 采纳 |
| --- | --- |
| 定时任务 = 触发条件 + 执行主体 + 一次运行 | 采纳，即本包四个领域对象 |
| 每次触发 = 新建一次真实会话 | 采纳（AU-R-05） |
| cron/日历 + 时区为主，一次性与立即执行为补充 | 采纳（AU-R-02、03、06） |
| 运行记录是一等公民 | 采纳（AU-R-09） |
| 启用/暂停/立即运行/归档 + 未来运行时间预览 | 采纳（AU-R-06、07、08） |
| 失败必须可见，有并发/时长/预算上限 | 部分采纳：失败可见首期做；并发上限首期只做"同任务不重叠"，预算与时长上限后置 |
| 归属以个人级为主 | 采纳（AU-R-01） |

我们比市场多数产品更严的三处，是既有仓库口径，不因为对标而下调：持久 delivery/occurrence/run 标识、同次触发去重的真实幂等键、跨重启恢复与错过合并。市场产品里只有少数明确处理了这些。

## 5. 成功指标

不设人为截断的数字目标。以下为可观察结果，逐条对应验收用例：

1. 规则到期必产生一次运行，且不重复产生（AU01、AU02）。
2. 上一次运行未结束时的新触发被跳过并记录原因，不并行、不堆叠（AU04）。
3. Host 重启后错过触发合并为一次，且不与已发生的运行重复（AU05）。
4. 授权撤销或专家修订缺失时停止并给出可读诊断，不静默改用其他账号或最新组合（AU06）。
5. 每条运行都能定位到真实 Session，成果经资料库登记后可复用（AU03）。
6. 页面显示的下次运行时刻与实际触发时刻一致（AU07）。

## 6. 前置依赖与排期事实

- 台账现状：D12 `dependsOn ["D11"]`，D11 `dependsOn ["D10"]`，`currentStep` 为 `D04`，D12 状态 `todo`、无 evidence。
- 依赖性质：D12 依赖 D11 的是**专家团资产**。定时任务的最小可用只需"能创建一次会话 + 能解析一个执行主体（单专家或裸会话）"，即 D04 与 D10 的产物；专家团是增量而非前置。
- 因此存在一个可选解耦点：把 D12 的 `dependsOn` 由 `["D11"]` 调整为不依赖 D11。这属于范围与顺序变更，必须先更新 [PLAN.md](../../PLAN.md)、[development-order.json](../../development-order.json) 与相应 ADR，不自行改动。
- 首期模块版本线：自动化模块 `0.1`，开发制品 `0.1.0-alpha.N`。开始实际开发时在 [modules.json](../../modules.json) 写入 `moduleVersion`。
