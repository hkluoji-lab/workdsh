# ADR-0034：企业门户与边缘登录门禁

状态：Accepted（用户 2026-09-23 裁决：同域路径分流 + 新增独立模块 portal + 复用同组 `DSH_AUTH_*` + 首页四段 + 只放联系方式）。日期：2026-09-23。

## 背景

`https://dsh.10ge.cn` 当前公网匿名可直达工作台，且容器内可执行 shell。2026-09-18 按用户要求移除了 Caddy `basic_auth` 之后，访问链上**不存在任何身份校验**：Cloudflare 隧道（宿主 `cloudflared` 进程，`dsh.10ge.cn` 的 ingress 由 Cloudflare 面板远端托管）→ 宿主 `0.0.0.0:3080` → 容器内 Caddy `:8443` → `dsh` 后端 `127.0.0.1:3080`。

同时用户要求该站点具备企业对外门户：打开网站先经过登录，登录页与首页承担「这是什么产品、能做什么、如何私有化与联署定制」的介绍职责，参照 `https://www.workbuddy.cn/` 的阅读顺序。

登录门禁有一个不可绕过的时序约束：**它必须早于应用加载**，因此不可能实现为 Harness 功能插件——插件由 Loader/Profile 在应用启动后装配，无法拦截插件加载之前的请求。

## 决策

1. **门户与门禁属于部署边缘层，不是功能插件。** 不接入 `dsh.bundle` / preset / Cordis 生命周期，不注册任何 Agent 工具、Slot 或 Remote，不拥有任何领域数据，不建立第二套账号、组织或审计真源。
2. **同域路径分流，应用仍留在根路径。** 门户占 `/portal`、`/portal/*`、`/login`、`/logout`、`/api/portal/*`；`/` 未登录时给门户首页、已登录时放行工作台；其余路径先验签名 Cookie，有效放行到 `127.0.0.1:3080`，无效 302 到 `/login?next=` 并在登录后回跳。DSH 不动、Cloudflare 不动、镜像不动，**回滚＝还原派生 Caddyfile 与派生 entrypoint 并重启容器**。
3. **代码落 `packages/portal`**，独立模块版本线 `0.1`，与 `website/`（GitHub Pages 开源官网）各自版本。形态为静态站 + 单文件 Node 服务，仅用 Node 内置模块、无构建、无运行时依赖。选 `packages/` 而非仓库根目录，是为了让门禁脚本的模块登记规则（模块路径必须匹配 `packages/*`、`packages/{plugins,providers}/*`、`examples/*`）能够覆盖它，并让版本与台账同源；选它而非 `packages/plugins/*`，是因为它不具备插件生命周期与业务对象。
4. **凭据复用同一组 `DSH_AUTH_USERNAME` / `DSH_AUTH_PASSWORD`**，不引入第二套口令。门户只做校验，不落库、不注册、不改写该环境变量。会话签名密钥由同一口令经 `createHmac('sha256','workdsh-portal-session-v1')` 派生，因而重启后会话仍有效、改口令即全量失效，无需新增密钥管理。
5. **会话是无状态签名 Cookie**：`HMAC-SHA256` 签名、`HttpOnly`、`SameSite=Lax`、生产 `Secure`，载荷只含用户名与签发/过期时间。服务端不保存会话，不写库。失败按来源 IP 限流（进程内滑动窗口，15 分钟 / 10 次）：表单请求转 303 到 `error=throttled`，JSON 请求返回 429。
6. **登录事件只写门户自有结构化日志**（stderr 单行 JSON），不写 audit 插件的数据表、不进入 Harness 会话日志。门户与业务审计是两个真源，禁止互相写入。
7. **不提供未实现能力的入口。** 当前只有一组凭据，登录页只写「忘记密码请联系管理员」，不放自助重置；企业微信/钉钉/SSO 登录按钮在 `identity-oidc`（B5）真实可用前不放置；页脚只放真实联系方式，不做提交表单，因此不收集任何个人信息；案例分区在获得真实客户授权前只做能力证明，不编造客户 logo 或证言。
8. **官网文件与产品截图复用**，不自造素材：门户引用仓库内已发布的真实应用截图，缺失即在部署时提供，不用占位图或生成图充数。

## 权衡与失败边界

- 门户成为公网唯一入口，可用性要求高于普通页面；门户服务不可用时 `forward_auth` 失败会导致整站不可达。部署时必须同时给出回滚方式（还原派生 Caddyfile 与派生 entrypoint 并重启容器），并先验证 `caddy validate`。具体增量与回滚命令见 [packages/portal/README](../../packages/portal/README.md) 的「部署」节。
- `forward_auth` 对每个受保护请求增加一次本机子请求。这是本地环回开销，P0 接受；若观测到明显延迟，再评估在 Caddy 侧缓存校验结果。
- 派生 Caddyfile 与镜像版本耦合：镜像升级后官方 Caddyfile 若有变更，派生副本会静默过期（此坑已有记录，见 ADR-0028）。升级前后必须比对。
- 门禁只做「是不是已登录的本人」，**不做组织、角色与资源授权**。这类判断仍归 access/audit/identity 插件，门户不得据 Cookie 内容放行任何业务操作。
- 口令校验与限流是进程内状态，多副本部署时会话校验仍然正确（无状态签名），但限流计数不共享。当前单实例部署接受该限制。
- 门户页面属于「公网营销面」，允许使用营销式主标题与品牌色；该豁免只在其自身章节内有效，不得回流污染工作台（见 [UI-DESIGN](../UI-DESIGN.md) 第 19 节）。
- 未验证边界：本 ADR 只覆盖本机服务契约与页面渲染。线上路由切换、`forward_auth` 的实际行为、以及容器内 Caddy 的语法校验必须单独执行并按证据登记，不得由本 ADR 的实施推断。

## 被否决的替代

1. **把登录做成功能插件。** 时序上不可能：插件在应用装配后才生效，无法在应用加载前拦截请求。
2. **恢复 Caddy `basic_auth`。** 浏览器原生弹窗无法承载登录页宣传、无退出登录、无失败限流、无登录后回跳，且 2026-09-18 已按用户要求移除。
3. **独立域名或子域门户。** 需要在 Cloudflare 面板新增 ingress 并改动远端托管配置，违反本轮「不动 Cloudflare」的约束；跨域还会引入 Cookie 域与 CORS 复杂度。
4. **门户自带反向代理（portal 直接转发到 3080）。** 会让门户承担 SSE 透传与全站代理职责，与 Caddy 的既有职责重复，构成第二套 transport；且 `forward_auth` 已能表达同一语义。
5. **在门户内自建账号库与线索表单。** 会造第二套身份真源与个人信息收集面，违反「组织、主体、授权从 P0/P1 起统一为服务端真源」的约束。

## 范围

不改上游 dsh、不改官方 Web 客户端、不改 Cloudflare 隧道配置、不改容器镜像与官方 entrypoint 本体；门户服务沿用既有的「派生 Caddyfile + 派生 entrypoint + 宿主目录即容器 `/data/dsh`」做法拉起（与 `/survey` 同构），因此不需要新增任何挂载。门户不注册 Agent 工具、不持有凭据明文、不写业务数据、不承担任何业务授权判断。企业 SSO、多账号、组织身份与登录审计归 B5 的 `identity-oidc` 与审计插件，门户只保留退出与跳转，不复制其职责。
