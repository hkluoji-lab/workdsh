01依托的底座

不是一个套壳对话框。

WorkDSH 站在 DeepSeek Harness 之上构建：执行循环、技能解析、插件装配、运行隔离与模型接入都由该底座提供，WorkDSH 负责企业业务对象、授权、修订与交付。

  • 官方执行循环与技能解析

    任务拆解、工具调用、长任务执行与上下文处理由 Harness 提供；不在外层再造第二套 Agent 循环。

  • 原生插件机制

    专家、技能、连接器、资料库与办公能力都是可安装、可卸载的功能插件，通过公开契约与会话投影组合。

  • 运行隔离与审批

    命令执行与文件写入走官方沙箱与审批管线；插件的可见范围不等于权限，实际操作仍需服务端检查。

  • 模型可替换

    模型经官方适配器接入，凭据由企业侧提供，与业务数据和对话内容分离管理。

  • 真实文件产出

    产物是可直接交付的文件，不是聊天记录里的代码块；原件可在会话内预览。

  • 企业级能力建设中

    企业 SSO、组织与跨组织隔离、用量与统计正在推进，本页不作交付承诺。

03私有化与联署定制

把智能体放进你的内网，按你的业务长出来。

我们提供三种交付形态，并在方案阶段逐项写清数据流向、账号接入方式与验收口径。

  • 公网 SaaS

    快速验证。使用托管实例评估能力与流程，适合先做概念验证再决定部署形态。

  • 企业私有化部署

    应用与数据部署在企业自己的服务器或私有云，由企业掌握运行与账号体系。

  • 混合部署

    控制面在外、数据面在内的组合形态，按业务敏感度逐层划分边界。

数据与凭据边界

  • 连接定义、连接实例与账号凭据三者分离；实例由使用者显式选择，不做跨账号回退。
  • 凭据不进入对话内容、前端页面、导出包与运行日志。
  • 私有化部署把应用与数据放在企业内网；是否出网取决于所选模型与连接器，我们在方案中逐项列出，不作无条件承诺。
  • 业务操作按权限检查并留下审计记录；组织与跨组织隔离随企业版推进。

六步定制流程

  1. 需求澄清业务场景、参与角色、数据边界与验收口径。
  2. POC 验证在隔离环境用真实数据跑通一条端到端链路。
  3. 定制开发按需开发技能、专家、连接器与业务页面。
  4. 联调验收联接内部系统，按验收清单逐项确认。
  5. 上线与培训私有化部署、权限与审计配置、管理员与使用者培训。
  6. 持续迭代技能与专家按修订演进，新版本不覆盖历史记录。

联署定制的交付物清单

  • 私有化部署包、部署说明与回滚方式
  • 定制技能包与专家定义（含版本与修订记录）
  • 连接器定义与企业侧账号接入说明
  • 权限、审计与运行隔离配置
  • 使用手册与管理员培训

常见问题

可以只用我们内网的模型吗？

模型经官方适配器接入，凭据由企业侧提供。具体可用范围取决于所选模型服务与部署形态，我们在方案阶段确认。

能对接我们已有的 OA、CRM 或数据库吗？

连接器以 MCP 接入外部系统，已具备多实例接入与工具发现能力，并已实测对接第三方文档服务。具体系统的接入方式与账号方案在联调阶段确定。

和直接使用对话式 AI 工具有什么区别？

区别在于执行与交付：它自主规划并调用工具完成任务，产出的是可交付文件，过程与结果可留痕、可审批，而不是一段需要你自己复制的回答。

现在哪些能力可以直接用？

技能资产、连接器、资料库、办公文档产出与单专家绑定已在本版本运行；项目空间、定时自动化、专家团 SOP、企业后台与企业 SSO 仍在建设中。
